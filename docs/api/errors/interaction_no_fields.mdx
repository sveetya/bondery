## When this happens

A domain rule blocked the operation after validation. Affects **Interactions** operations.

## What your integration should do

Verify interaction id, participant ids, and that at least one field is being updated.

## What end users should see

Translate with `common.errors.api.interaction_no_fields` when a string exists; otherwise map by domain prefix. Never surface the raw API `message`.

## Response fields

| Property | Value |
|----------|-------|
| **Type** | `invalid_request_error` |
| **HTTP status** | 400 |
| **code** | `interaction_no_fields` |
| **doc_url** | `/docs/api/errors/interaction_no_fields` |

The API `message` field is for developers debugging in logs. Product UI must key off `code` (and `details` for validation).
